## Mail operations

Open **Master PC → البريد والبحث والخزنة → خزنة الحسابات** to add SMTP/IMAP credentials. The account form supports Gmail app passwords or custom SMTP (465 with TLS, or 587 with required STARTTLS) and IMAP 993 with TLS. Gmail accounts must allow IMAP/app passwords; OAuth-only accounts are not supported by this connector. TLS certificates are always verified. Connections resolve and pin public IP addresses, rejecting private/reserved destinations.

Connection secrets and optional browser storage state are encrypted with AES-256-GCM using the existing runtime `VAULT_ENCRYPTION_KEY`, bound to organization, connection and purpose. Only connection metadata is returned. Mail contents and operational records reside in owner-isolated Netlify Database tables. The authenticated client uses quiet API calls to keep mail, credentials and audio outside the general inspector.

The connection test verifies SMTP and fetches the inbox. Manual sync and an every-minute scheduled function fetch the latest 30 messages without loading remote images or executing email HTML. The scheduled function processes one eligible mailbox per invocation, oldest attempted first; an account is eligible after five minutes. This is bounded polling, not IMAP IDLE or complete historical import, and latency grows with the number of accounts. Incoming messages deduplicate by account, UIDVALIDITY and UID. Attachments are not imported, and large messages are bounded/truncated.

Chat/voice can request the inbox, draft an email to an explicitly supplied address, or draft a reply to the latest fetched message. Requests from another employee can hand off to the mail specialist, including a research summary. With multiple mailboxes, the user selects an account in the mail panel. The model receives no credentials and cannot send. The user reviews the actual recipient, subject and body in the panel, edits if needed, and chooses **اعتماد وإرسال**. Manual compose uses the same approval path.

Sending atomically claims an unchanged draft, assigns a stable Message-ID, and records SMTP acceptance, rejection or an unknown outcome. Unknown/in-progress attempts are never automatically resent. An explicit reconciliation action searches the provider's Sent folder by Message-ID; lack of a copy remains inconclusive because SMTP servers do not universally archive outgoing mail. SMTP acceptance does not prove recipient delivery or reading. The older freeform task-approval flow remains separate from structured mailbox approval and cannot send email.

## Research and portal navigation

The researcher chat and Master PC research panel perform grounded web search with Gemini 2.5 Flash through Netlify AI Gateway. Results require returned source metadata and retain source links alongside the summary. A missing grounding result is an error, not a claim of live research. Web content is untrusted evidence and cannot authorize sending or other external actions.

Portal accounts accept a login URL, username/password and an optional encrypted-session preference. A Playwright/Chromium worker runs inside the server function, attempts conventional same-origin login forms, checks for recognizable account UI, reads the landing page and follows up to two relevant same-origin links. Each page's title, sanitized URL and text excerpt is persisted as it is read and appears in Master PC through polling. This is a view of recorded page evidence, not a video stream or an iframe authenticated with stored credentials.

All browser HTTP requests are intercepted and fulfilled through size/time-limited HTTPS sockets pinned to validated public IPs. Cross-origin requests, WebSockets, service workers, downloads and post-login non-read requests are blocked. The browser has no general model execution tool, and credentials/session tokens are never supplied to the model. Sessions can be encrypted for at most 12 hours; otherwise an identifiable logout is attempted and the isolated browser context is destroyed. Deleting a saved session removes our session copy, but does not guarantee global provider-side token revocation.

This connector does not guarantee login to arbitrary sites. Cross-origin SSO, MFA, CAPTCHA, unusual forms, sites requiring third-party resources, and apps needing POST requests for read queries can require manual intervention or a dedicated adapter. The UI explicitly reports these limits. Purchases, publishing, account modifications and unrestricted website automation are not implemented. The provider's authenticated page evidence must be checked on deployment before treating a platform as supported.

## Voice and deployment prerequisites

The integrated microphone/Space control enables spoken replies and requests audio permission immediately. Browser recognition is preferred, with automatic MediaRecorder/Gemini transcription fallback for supported service/language failures. Speech uses available matching device voices; missing or failed voices fall back to the official Azure Speech SDK through an authenticated synthesis endpoint. Azure fallback requires runtime `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION` configured through the administration panel. It supports Arabic and the other seven output languages without requiring an installed device voice. Missing configuration, permission refusal, playback blocking and provider errors remain visible beside the written response; speech cannot be guaranteed without those prerequisites.

Microphone and synthesized-audio resources are cancelled on interruption, hidden tabs, account changes and unmount. Transcript/response text persists; audio recordings and synthesized clips are not stored by the application. Audio can be processed by browser speech services, Gemini transcription or Azure synthesis depending on the route. This remains sequential recognition/generation/synthesis, not native simultaneous duplex audio.

New generated schema migrations and an additive employee seed accompany this change. Previously applied migrations were preserved and no migrations were applied manually. Chromium binaries and server SDKs are included in the function packaging configuration. The platform must validate packaging, function memory/cold starts, the scheduled mailbox function, database migration, grounded search, and authenticated SMTP/IMAP/portal/speech behavior on the deployed environment. Build, typecheck, test and dev-server commands were not run during the agent session, per repository policy; edited sources and migrations were inspected and formatted instead. No successful deployment, delivered email, universal portal compatibility or domain transfer is claimed. Existing TLS, merchant, core callback and DNS/domain prerequisites remain unchanged.
