# Flagship experience and application release

The flagship homepage now uses an obsidian, warm titanium, champagne and muted emerald palette. A lazy-loaded Three.js aperture sculpture links to the five external applications through accessible HTML links. GSAP provides the entrance and pointer motion. Touch interaction does not capture page scrolling, and keyboard users can reach the same links without the canvas. A static composition remains when WebGL cannot initialize or loses its context. The scene respects reduced motion, has a pause control, caps pixel density and stops its animation loop outside the viewport or when the document is hidden. Refresh rate depends on hardware and browser; 120 fps has not been measured or guaranteed.

The optional focus setting changes the lighting for the current page. Ambient audio begins only after a click, uses a quiet local Web Audio chord and feeds its real analyser into the sculpture. It stops on page hide and unmount. It makes no therapeutic or frequency-treatment claims, captures no microphone input and saves no preference. The package guide uses browser speech synthesis on demand; availability of an Arabic voice depends on the device. Recommendations are deterministic matches of category, currency and budget against the current catalog. The existing authenticated AI team remains the route for a personalized conversation; no AI model or inference configuration was changed.

Traditional photography, production and advertising services are read from the existing database and presented with their unchanged prices, starting-price labels and billing periods beside the digital-team offer. All production entries can be expanded, and existing product detail and inquiry/checkout routes remain in use. The savings calculator has editable, explicitly hypothetical monthly assumptions; it never claims recorded business savings or equivalent photography deliverables. Zero-cost and negative-savings scenarios remain visible. All original policy content remains in place, and the flagship now repeats the original storefront business/footer content and every policy link. No registration number or legal certification was invented.

The existing eight-language service descriptions remain. New experience controls and copy use Arabic and English, with English fallback for the other language selections. A complete localization of the new controls into the six remaining languages is not claimed.

## PWA and Web Push

The install control uses the real browser install event and device-specific instructions. The manifest keeps its existing app identity and launch URL and adds Arabic metadata and shortcuts. The service worker caches a dedicated public offline page, calculator script, logo/icons and bounded public script/style/font assets. It never caches application navigations, APIs, Identity, SSO, order state, chats or other private responses. The offline calculator is temporary page state, not saved data. New workers activate through the normal service-worker lifecycle without forcing a reload over unsaved work.

Notification registration requires a signed-in Identity account and explicit browser permission. Endpoints and encryption keys are encrypted in Netlify Database using account/subscription-bound authenticated encryption; only an endpoint digest is indexed. A new additive migration, `20261019090822_add_push_subscriptions`, creates that table. Existing migrations are unchanged. The platform applies the migration; do not apply it manually.

The account can enable notifications on its device, send itself a generic test, and unsubscribe. Server routes verify account ownership, enforce rate limits, restrict outgoing requests to recognized browser push providers and use HTTPS. Test messages include no order, conversation, financial or personal details. Acceptance by the push provider is reported separately from notification display. Unknown delivery outcomes are not retried automatically. Expired endpoints are removed after provider 404/410 responses, and a daily maintenance task removes subscriptions after 90 days. Automatic task/order campaigns and native APNs/FCM delivery are not enabled by this release.

Configure `ONESHOT_PUSH_PUBLIC_KEY`, `ONESHOT_PUSH_PRIVATE_KEY` and an optional `ONESHOT_PUSH_SUBJECT` in the server runtime through administration. Generate the VAPID pair once using a secure administrative process; do not paste credentials into source or logs. The existing vault encryption key is required. The public VAPID key is intentionally delivered to the browser by the configuration endpoint; its private counterpart and subscription encryption material stay on the server. Changing the VAPID pair requires devices to unsubscribe and enroll again. Notifications show an awaiting-configuration state until these dependencies are available. iPhone Web Push requires a supported iOS version and a Home Screen installation, and does not imply WKWebView push support.

## iOS and Android source projects

`ios/` and `android/` contain generated Capacitor 8 native projects with the OneShot app identifier, icons, launch artwork, a bundled public offline page/calculator and the standard app, browser, haptic, status-bar and splash plugins. Microphone access is declared for the existing opt-in voice workflows. Cleartext traffic and Android backups are disabled. The web bridge handles the Android back button, optional tactile feedback and external links in an OS browser surface.

The current wrapper loads the verified HTTPS production origin, preserving existing Identity and API origin behavior; it does not package the full web application for offline use. This is a hosted-content wrapper configuration, including Capacitor's external-server setting. That setting is documented by Capacitor for development/live reload, so these sources must be treated as a device-review candidate, not a production-store-ready binary. A store release requires validating this hosting model against current Apple/Google policies or replacing it with bundled web assets and an explicitly reviewed native authentication/API integration. No permissive CORS or wildcard navigation was introduced to bypass that decision. Existing browser-based OAuth, external SSO and checkout return flows need device verification before release.

After dependency installation, `pnpm native:sync` refreshes the public offline shell and copies plugin configuration into the platform projects without compiling an application. `pnpm native:ios` opens Xcode; `pnpm native:android` opens Android Studio. Use the committed lockfile. iOS compilation/signing requires macOS, Xcode and an Apple Developer team; Android requires a compatible JDK/SDK, a private signing key and a Play Console account. Configure bundle/application identifiers, signing, versioning, screenshots, privacy disclosures and store policy compliance in those release environments. Do not commit certificates, signing keys or service configuration secrets. No signed APK/AAB/IPA or store listing was produced here.

Published store links can be set as `ONESHOT_IOS_STORE_URL` (an HTTPS apps.apple.com application URL) and `ONESHOT_PLAY_STORE_URL` (an HTTPS play.google.com/store/apps/details URL). Those operator-configured links are validated for host/path but are not a claim that a store approved the application. The existing independently checked APK download configuration is retained. Do not set download links until the corresponding release exists and has been verified.
